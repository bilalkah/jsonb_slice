# 0.5.0

Release type: optional transparent access.

## Purpose

This release lets existing built-in JSONB accessor syntax use `jsonb_slice`
in supported plan expressions. A user does not need to replace each built-in
operator with an extension operator to run the experiment.

Transparent mode is off by default. The explicit extension functions and
operators from 0.4.0 remain unchanged.

## Enable the mode

Load the library before PostgreSQL plans the query. Then enable the setting:

```sql
LOAD 'jsonb_slice';
SET jsonb_slice.transparent = on;
```

For example:

```sql
SELECT document ->> 'name'
FROM records;
```

In a supported plan expression, the executor can call
`jsonb_slice_get_text(jsonb, text)` instead of
`jsonb_object_field_text(jsonb, text)`.

## Supported accessors

| Built-in form | Extension function |
|---|---|
| `jsonb -> text` | `jsonb_slice_get(jsonb, text)` |
| `jsonb -> integer` | `jsonb_slice_get(jsonb, integer)` |
| `jsonb ->> text` | `jsonb_slice_get_text(jsonb, text)` |
| `jsonb ->> integer` | `jsonb_slice_get_text(jsonb, integer)` |
| `jsonb #> text[]` | `jsonb_slice_path(jsonb, text[])` |
| `jsonb #>> text[]` | `jsonb_slice_path_text(jsonb, text[])` |

Direct calls to the six matching built-in PostgreSQL functions use the same
replacement rules.

## Plan scope

The mode inspects common select lists and filters. It follows common child
plans, append-style child lists, and planned subqueries.

Some PostgreSQL plan nodes store expressions in special fields. This release
does not inspect every special field. A call outside the supported scope stays
as a PostgreSQL built-in call. The query result remains correct.

## Safety rules

The hook runs after PostgreSQL creates the plan. It keeps the selected scan,
join, sort, aggregate, and index choices.

Before a replacement, the extension verifies:

- extension ownership;
- function schema and argument types;
- C library and symbol;
- result type and function properties;
- `PUBLIC EXECUTE` on the built-in and replacement functions.

Function and permission decisions become plan dependencies. A relevant
catalog change invalidates a cached plan. A change to
`jsonb_slice.transparent` resets the session plan cache.

The statement must read an eligible relation with a JSONB column declared as
`STORAGE EXTERNAL`. This is only a planning gate. At execution time, each
stored value still selects its read path:

```text
external and uncompressed -> TOAST slices
inline or compressed      -> PostgreSQL complete-value fallback
```

## Loading boundary

`CREATE EXTENSION` installs the functions and operators. It does not load the
planner hook in every session. Use `LOAD 'jsonb_slice'` before planning, or
configure `session_preload_libraries = 'jsonb_slice'` and start a new session.

## Verification

The regression tests cover:

- all six built-in operators and direct functions;
- transparent mode on and off;
- external, inline, and compressed stored values;
- function identity and permission changes;
- prepared-plan invalidation;
- relation storage changes;
- common child plans, append branches, and subplans;
- fresh installation and upgrade from 0.4.0.

## Boundary

This release is an experiment. It makes no general performance claim. It does
not change PostgreSQL's JSONB storage format or its built-in operator catalog.
